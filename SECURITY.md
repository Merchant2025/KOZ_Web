# Безопасность

Не публикуйте сведения об уязвимостях в открытых Issues. Передайте описание владельцу репозитория приватным способом.

Для Netlify заголовки безопасности задаются в корневом файле `_headers`. Production-ответы по HTTPS должны содержать как минимум:

- `Content-Security-Policy` с директивой `frame-ancestors 'none'`;
- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Strict-Transport-Security: max-age=31536000` после постоянного включения HTTPS.

HSTS нельзя включать до проверки HTTPS на production-домене. `includeSubDomains` и `preload` можно добавлять только после отдельного подтверждения готовности всех поддоменов и необратимых последствий регистрации preload. При смене платформы публикации эти заголовки необходимо перенести в поддерживаемую ею серверную конфигурацию и проверить на фактическом HTTPS-ответе; CSP в HTML не заменяет заголовок, поскольку `frame-ancestors` в meta-CSP не работает.

Изменения CSP должны сохранять принцип минимальных разрешений. Формы разрешается добавлять только вместе с серверной валидацией, защитой от CSRF и документированным порядком обработки персональных данных.
