# Реестр репозиториев и окружений KOZ Web

Этот документ — операционный реестр исходного кода, автоматизации и мест
развёртывания KOZ Web. Он не является хранилищем секретов. Реестр необходимо
обновлять при создании, переносе, архивации или удалении любого ресурса.

Дата последней проверки: **2026-08-11**.

## Правила ведения

- Владелец — человек или команда, которые подтверждают изменения жизненного
  цикла ресурса. `Не назначен` означает, что ответственного нужно определить до
  публикации или удаления.
- Статус может быть `active`, `inactive`, `archive-candidate` или `archived`.
  Неизвестный статус отмечается как `требует подтверждения`, а не угадывается.
- В колонке «Секреты» указываются только имена или типы секретов и место их
  хранения. Значения секретов в этот документ и в Git не добавляются.
- Запись `не настроено / не подтверждено` означает, что конфигурация не найдена
  в репозитории и должна быть уточнена у владельца инфраструктуры.
- Срок хранения отсчитывается с момента создания резервной копии или архива.
  Если срок не утверждён, ресурс нельзя безвозвратно удалять.

## Безопасное обращение с секретами

Запрещено коммитить токены, пароли, приватные ключи, deploy credentials и
содержимое `.env`. Файлы `.env` и `.env.*` игнорируются Git (кроме допустимого
шаблона `.env.example`, который может содержать только пустые значения или
безопасные примеры). Перед каждым push следует проверить staged diff и имена
файлов, например:

```bash
git diff --cached
git diff --cached --name-only
```

Если секрет попал в Git, одного удаления файла недостаточно: секрет нужно
немедленно отозвать/ротировать, уведомить владельца, очистить историю
согласованным способом и проверить зеркала, кэши CI и резервные копии.

## Порядок архивации и удаления

Любой репозиторий, runner, локальный клон, сервер или окружение удаляется только
отдельной согласованной операцией. Массовое удаление по этому реестру запрещено.

1. Изменить статус конкретной записи на `archive-candidate`, указать причину,
   дату, инициатора и планируемую дату удаления.
2. Получить явное подтверждение указанного владельца. Если владелец не назначен
   или не ответил, удаление остановить.
3. Создать резервную копию либо проверить существующую: зафиксировать её место,
   дату, контрольную сумму, шифрование, доступ и срок хранения. Секретные
   реквизиты доступа в реестр не записывать.
4. Выполнить тест восстановления в изолированном месте и сохранить результат
   проверки. Для Git убедиться, что доступны необходимые ветки, теги и история.
5. Согласовать отдельную операцию удаления, её окно, исполнителя и rollback с
   владельцем. Сам статус `archive-candidate` разрешением на удаление не является.
6. После операции записать дату и результат: `archived`, если ресурс сохранён в
   архиве, либо удалить запись только после окончания обязательного срока
   хранения, оставив аудиторское свидетельство операции.

Минимальная карточка кандидата:

```text
Ресурс:
Причина и инициатор:
Статус: archive-candidate
Владелец и подтверждение:
Резервная копия (место без секретов, дата, checksum, срок хранения):
Результат теста восстановления:
Согласованное окно и исполнитель удаления:
Итог и дата:
```

## Необходимые уточнения

Владелец инфраструктуры должен заменить все отметки `Не назначен`, `требует
подтверждения` и предложенные сроки на проверенные сведения. В первую очередь
нужно зафиксировать основной Git URL, владельцев репозитория и CI, список
рабочих станций, наличие Git-зеркал, а также подтвердить отсутствие тестовых и
production-серверов.
